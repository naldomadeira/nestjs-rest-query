---
title: NestJS Prerequisite
description: Requirements for using nestjs-rest-query in a NestJS application with TypeORM.
---

Before installing the library, confirm that your NestJS project already meets the requirements below.

This library was designed for NestJS applications that use TypeORM and have decorators enabled. If that is your scenario, the setup is usually simple.

## NestJS application

| Requirement | Minimum version | Note                                                                                           |
| ----------- | --------------- | ---------------------------------------------------------------------------------------------- |
| **NestJS**  | `^11.0.0`       | The library was designed for NestJS projects with `@nestjs/common` and `@nestjs/core` present. |

## Runtime

| Requirement | Minimum version |
| ----------- | --------------- |
| **Node.js** | `>= 20`         |

## Peer dependencies

These packages must be present in your project — they are **not** included in the library.

| Package            | Minimum version | Required |
| ------------------ | --------------- | -------- |
| `@nestjs/common`   | `^11.0.0`       | Yes      |
| `@nestjs/core`     | `^11.0.0`       | Yes      |
| `typeorm`          | `^0.3.26`       | Yes      |
| `reflect-metadata` | `^0.2.0`        | Yes      |
| `@nestjs/swagger`  | `^11.0.0`       | Optional |

If your project is not using NestJS yet, start by creating the application with `nest new`. The library depends on the framework ecosystem for decorators, metadata, and dependency injection.

`@nestjs/swagger` is only required if you want to generate OpenAPI documentation with `@ApiDynamicQuery` and test filters through the Swagger UI. See the [Swagger](/docs/swagger) section for details.

## TypeORM

The library is built on top of TypeORM's `QueryBuilder`. All filter, sorts, fields, includes, and pagination logic is applied to a `SelectQueryBuilder` generated from your `Repository`.

This means:

- You need to have TypeORM configured with at least one database (PostgreSQL, MySQL, SQLite, etc.)
- Your entities must use TypeORM decorators (`@Entity`, `@Column`, `@ManyToOne`, etc.)
- `QueryBuilderService` operates exclusively on TypeORM repositories — there is no support for raw query or other abstraction layers

<Callout type="info">
  🔭 **Roadmap — Prisma and Drizzle**

Current support is exclusive to TypeORM. In the future, we intend to bring the same experience to **Prisma** and **Drizzle** — keeping the same decorators API and the same whitelist-based security contract, only swapping the query engine underneath.

</Callout>
