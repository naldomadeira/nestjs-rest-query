## Instale o pacote

```bash tab="pnpm"
pnpm add nestjs-rest-query
```

```bash tab="npm"
npm install nestjs-rest-query
```

```bash tab="yarn"
yarn add nestjs-rest-query
```

<Callout type="warn">
  A API `3.x` descrita nestas páginas ainda não está no npm — `2.1.0` é a última
  versão publicada. Até a `3.0.0` sair, o código daqui corresponde ao fonte da
  linha `main` do repositório e às quatro aplicações de exemplo, não ao tarball
  que o comando acima baixa.
</Callout>

Depois instale o ORM que você usa. Todos os peers de ORM são opcionais e o
entrypoint raiz não carrega nenhum, então você instala exatamente um:

```bash tab="TypeORM"
pnpm add typeorm @nestjs/typeorm
```

```bash tab="Prisma"
pnpm add @prisma/client
pnpm add -D prisma
```

```bash tab="Drizzle"
pnpm add drizzle-orm postgres
```

## Configure o bootstrap

Três ajustes são necessários no `main.ts` para a biblioteca funcionar
corretamente.

### 1. Query parser estendido

```typescript
app.set('query parser', 'extended');
```

O Express 5 trocou o parser de query padrão de `qs` (estendido) para `simple`. A
biblioteca espera que parâmetros como `?filter[name][eq]=foo` sejam expandidos
em objetos aninhados pelo framework antes de chegarem ao controller — e isso só
acontece com o parser `extended`. Sem ele, um filtro é aceito em silêncio e
nunca aplicado.

### 2. ValidationPipe com conversão implícita

```typescript
app.useGlobalPipes(
  new ValidationPipe({
    transform: true,
    transformOptions: {
      enableImplicitConversion: true,
    },
  })
);
```

A `DynamicQueryDto` tipa `page`, `perPage` e `paginate` como `string`, porque é
isso que chega no fio. A biblioteca faz o parse e a validação por conta própria —
`?page=abc` é `400 PAGINATION_INVALID`, nunca uma queda silenciosa para a
página 1.

### 3. Interceptor do Swagger (opcional)

```typescript
import { dqbSwaggerRequestInterceptor } from 'nestjs-rest-query';

SwaggerModule.setup('/', app, document, {
  swaggerOptions: {
    requestInterceptor: dqbSwaggerRequestInterceptor(document),
  },
});
```

A Swagger UI serializa filtros como vários query params
(`filter[name][eq]=foo`). Sem o interceptor, o navegador envia esses parâmetros
de uma forma em que o Express pode não preservar corretamente a notação de
colchetes. O `dqbSwaggerRequestInterceptor` reescreve a URL antes do envio,
garantindo que os filtros cheguem ao controller no formato esperado.

<Callout type="info">
  Este interceptor só é necessário para testar filtros pela Swagger UI. Clientes
  externos (Postman, aplicações de frontend, etc.) montam a URL diretamente e
  não precisam dele. A seção [Swagger](/pt-BR/docs/swagger) explica o cenário
  completo.
</Callout>

### Exemplo completo

```typescript title="main.ts"
import { NestFactory } from '@nestjs/core';
import { NestExpressApplication } from '@nestjs/platform-express';
import { ValidationPipe } from '@nestjs/common';
import { DocumentBuilder, SwaggerModule } from '@nestjs/swagger';
import { AppModule } from './app.module';
import { dqbSwaggerRequestInterceptor } from 'nestjs-rest-query';

async function bootstrap() {
  const app = await NestFactory.create<NestExpressApplication>(AppModule);

  // Necessário para expandir filter[campo][op]=valor em objetos aninhados
  app.set('query parser', 'extended');

  app.useGlobalPipes(
    new ValidationPipe({
      transform: true,
      transformOptions: {
        enableImplicitConversion: true,
      },
    })
  );

  const document = SwaggerModule.createDocument(
    app,
    new DocumentBuilder().setTitle('Minha API').setVersion('1.0').build()
  );

  SwaggerModule.setup('/', app, document, {
    swaggerOptions: {
      requestInterceptor: dqbSwaggerRequestInterceptor(document),
    },
  });

  await app.listen(process.env.PORT ?? 3000);
}
bootstrap();
```

## Registre o módulo

Importe o `DynamicQueryBuilderModule` no `AppModule` raiz com `forRoot`. Toda
opção é **opcional** — `forRoot({})` já entrega os defaults:

```typescript title="app.module.ts"
import { Module } from '@nestjs/common';
import { DynamicQueryBuilderModule } from 'nestjs-rest-query';

@Module({
  imports: [
    DynamicQueryBuilderModule.forRoot({
      pagination: { defaultPerPage: 10, maxPerPage: 100 },
    }),
  ],
})
export class AppModule {}
```

O módulo é `@Global`, então você não precisa importá-lo nos módulos de feature —
o `QueryBuilderService` fica disponível na aplicação inteira automaticamente.

<Callout type="warn" title="Nenhum adapter aqui">

O `forRoot` configura apenas política comum. Não existe opção `adapter` nem
adapter default implícito: quem decide o adapter é a **source** que você passa
ao `execute()`. Passar `adapter` ou `operators` é recusado na inicialização com
`SOURCE_CONFIGURATION_INVALID` e a mensagem
`forRoot no longer accepts "adapter"; see the "2.x → 3.x" section of MIGRATION.md`.

</Callout>

## Opções de configuração

O `forRoot` aceita um objeto `QueryBuilderConfigV3`.

### `pagination`

| Opção            | Tipo     | Default | Descrição                                                  |
| ---------------- | -------- | ------- | ---------------------------------------------------------- |
| `defaultPerPage` | `number` | `20`    | Itens por página quando a requisição não traz `perPage`.   |
| `maxPerPage`     | `number` | `100`   | Teto. Um `perPage` maior é `400`, não um corte silencioso. |

As duas são validadas na inicialização: `defaultPerPage` abaixo de `1`, ou um
`maxPerPage` menor que o `defaultPerPage`, estoura
`SOURCE_CONFIGURATION_INVALID` enquanto o módulo carrega.

<Callout type="info">
  O `defaultPerPage` era `10` na `2.x` e é `20` na `3.x`. Fixe-o explicitamente
  se seus clientes dependem do tamanho de página antigo.
</Callout>

### `logging`

| Opção          | Tipo                                     | Default       | Descrição                                                              |
| -------------- | ---------------------------------------- | ------------- | ---------------------------------------------------------------------- |
| `enabled`      | `boolean`                                | `false`       | Habilita os logs internos.                                             |
| `level`        | `'error' \| 'warn' \| 'info' \| 'debug'` | `'info'`      | Nível mínimo emitido.                                                  |
| `redactValues` | `boolean`                                | `true`        | Redige valores de filtro e de busca antes de logar.                    |
| `logger`       | `LoggerLike`                             | Logger NestJS | Qualquer objeto com `error`/`warn`/`log`/`debug` (winston, pino, ...). |

```typescript
DynamicQueryBuilderModule.forRoot({
  logging: { enabled: true, level: 'debug' },
});
```

O log do plano em `debug` carrega apenas metadados — paths, operadores,
contagens, paginação — nunca os valores que o cliente enviou.

### `portability`

| Opção     | Tipo      | Default | Descrição                                                                  |
| --------- | --------- | ------- | -------------------------------------------------------------------------- |
| `enforce` | `boolean` | `false` | Exige que a source carregue os fatos do perfil certificado, e os verifica. |

Com `enforce: true`, uma source construída sem `portabilityProfile` é recusada
com `PORTABILITY_PROFILE_MISMATCH`, e o mesmo vale para um perfil cujo dialeto
não bata com o do adapter ou que falhe em `checkPortabilityProfile()`. Colete os
fatos uma vez, na subida, com `collectProfileFacts()`, e entregue-os à fábrica
da source — o caminho de requisição nunca consulta catálogos.

### `consistency`

| Opção         | Tipo                            | Default      |
| ------------- | ------------------------------- | ------------ |
| `consistency` | `'eventual' \| 'transactional'` | `'eventual'` |

<Callout type="warn">
  **Nenhum adapter entregue suporta `'transactional'` hoje.** TypeORM, Prisma e
  Drizzle reportam `transactionalConsistency: false`, então declará-lo faz toda
  requisição falhar cedo com `CAPABILITY_UNAVAILABLE` em vez de rodar dados e
  contagem sob snapshots diferentes. Deixe em `'eventual'`.
</Callout>

### `textProfile`

| Opção         | Tipo                                     | Default             |
| ------------- | ---------------------------------------- | ------------------- |
| `textProfile` | `'portable-strict' \| 'database-native'` | `'portable-strict'` |

Sob `portable-strict`, `ilike`, `notIlike` e `search` comparam uma coluna
dobrada declarada com um termo dobrado, então nenhum `ILIKE` e nenhum
`mode: 'insensitive'` é emitido.

<Callout type="info">
  Considere `'database-native'` reservado. O valor viaja no plano, mas nenhum
  adapter o lê: a dobra é aplicada pelo núcleo de qualquer forma. O único efeito
  observável hoje é que a verificação de `portability.enforce` é ignorada.
</Callout>
